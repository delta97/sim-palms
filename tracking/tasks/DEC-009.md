## Goal

The user picks the building footprint source used for false-positive rejection and cut clipping, based on a side-by-side comparison at the test block. Recorded in ADR-0010 before the SCAN-100 building adapter is written.

## Context

- Plans: `plans/02-detection-pipeline.md` sections 1, 3 and 6; `plans/01-architecture.md` region config `buildings: osm  # or microsoft_footprints`.
- Procedure: `plans/detailed/07-risks-and-open-questions.md#how-every-decision-task-runs`.
- Test block and bbox: ADR-0005 (DEC-004). License terms: `docs/licenses/data-sources.md` (RISK-001).
- Risks: R-03 (cuts damage buildings), R-07 (false positives).
- Options: (1) OSM via Overpass; (2) Microsoft Global ML Building Footprints; (3) union of both, deduplicated by overlap; (4) county or city outlines (LA County / LARIAC, SanGIS).
- Criteria: small-structure coverage (garages, sheds), alignment with aerial imagery, terms and attribution, download effort.
- Default if unclear: OSM.

## Steps

1. Download footprints for the ADR-0005 bbox from OSM (Overpass `building=*`) and Microsoft (the quadkey tile covering the bbox). Optionally the county dataset if easily available. Keep downloads under `data/` (gitignored).
2. In QGIS or geopandas: count buildings per source; count buildings in one source with no overlap in the other; note mean visual offset against aerial imagery for 5 sample buildings.
3. Pick the 5 palms closest to buildings (from the inventory) and note which source has the adjacent building outline.
4. Write `tracking/decisions/ADR-0010-building-footprint-source.md` (Status `proposed`) with a comparison table, license notes copied from RISK-001 (as quotes or links, no conclusions), and a recommendation.
5. User decides. Set Status `accepted`, fill Decision and Consequences: the `buildings:` value for region YAML, which adapter SCAN builds first, attribution needed.
6. Add one line under the building footprint section of `plans/detailed/02-detection-pipeline.md`: `Decided (ADR-0010): <choice>.` If that file does not exist yet, record the note in the ADR Consequences and skip.
7. Run `python3 scripts/tasks.py validate`.

## Acceptance criteria

- [ ] ADR-0010 exists with a comparison table holding counts per source for the test block.
- [ ] Status `accepted` by the user, or `proposed` with "Default applied provisionally".
- [ ] Consequences names the region YAML `buildings:` value.
- [ ] The detection plan carries the one-line decision note, or the ADR says why not.
