## Goal

The user decides whether the project stays personal or is published, and in what form, recorded in ADR-0002 before GATE-P6 and before any public upload.

## Context

- Plans: `plans/07-risks-and-open-questions.md` open question 1 and the licensing risk; `plans/05-phases.md` decision table ("Personal until data and model licenses are checked").
- Procedure: `plans/detailed/07-risks-and-open-questions.md#how-every-decision-task-runs`.
- Evidence: `docs/licenses/data-sources.md` (RISK-001), `docs/licenses/models-and-tools.md` (RISK-002), ADR-0012 region list (DEC-011), ADR-0003 provisional publish intent, `docs/compat/other-mods.md` (overlap with published mods).
- Options: (1) personal only; (2) publish region packages and `palmfix-assets` on flightsim.to; (3) publish tools only on GitHub (users build their own regions); (4) both.
- Criteria: no open license question blocks what would ship (the user decides how to treat each question; this task does not give legal conclusions); the user accepts support load (hours per month); assets are redistributable under ADR-0003's route.
- Default if unclear: personal.
- Risk: R-14. Kill criterion K7.

## Steps

1. Re-verify terms: re-open every terms URL in both license docs, compare with the recorded quotes, and append "Re-checked YYYY-MM-DD: unchanged / changed (details)" to each section.
2. Build a table: what would ship under each option × which sources and models it contains × terms status (clear / unclear / restrictive, from the audits) × open questions.
3. Ask the user: support hours per month they accept; answers to the open questions in the audits.
4. Write `tracking/decisions/ADR-0002-personal-or-publish.md` (Status `proposed`).
5. User decides. Consequences:
   - Personal: `python3 scripts/tasks.py set DEC-010 dropped --note "ADR-0002 personal"` and the same for RISK-009.
   - Publish (any form): DEC-010 and RISK-009 proceed; list release tasks to create (versioning per plan 04 `1.3.0+data2026-11` style, changelog, support notes, flightsim.to page) and name the owning area.
6. Add a one-line `Decided (ADR-0002): ...` note to the Phase 6 section of `plans/detailed/05-phases.md` (if missing, note in the ADR).
7. Run `python3 scripts/tasks.py validate`.

## Acceptance criteria

- [ ] Both license docs carry a re-check date from this task.
- [ ] ADR-0002 has the "what ships" table and the user's answers to open questions (or "unanswered").
- [ ] Status `accepted` (or `proposed` with default personal applied provisionally).
- [ ] DEC-010 and RISK-009 statuses match the decision.
