## Goal

`palmgen/ids.py` gives every exclusion polygon, scenery object and nested element a stable UUIDv5, plus a deterministic `[0,1)` hash per palm for heading and alternate picks. Rebuilds produce identical ids.

## Context

- Name-string scheme and formatting styles: plan section [GEN deterministic ids](../../plans/detailed/04-fs2024-integration.md#gen-deterministic-ids).
- ARCH owns the UUIDv5 helper in `palmcore.ids` (ARCH-006: `NAMESPACE`, `object_guid`, `format_guid`, `stable_unit_float`). Wrap it here; do not define a separate root namespace. If a palmcore signature differs from this plan, adapt inside this module.

## Steps

1. Implement `GUID_SCHEME = "v1"`, `polygon_guid(region, tile_id, member_ids, part=0)`, `object_guid(region, tile_id, palm_id)`, `tile_guid(region, tile_id)`, `child_guid(parent_name, role)`, plus `polygon_name(...)`/`object_name(...)` returning the name strings (the writer passes names to `child_guid`).
2. `polygon_name` sorts `member_ids` itself; empty `member_ids` raises `ValueError`.
3. `format_guid(u, style)` for `braces_upper`, `braces_lower`, `plain_upper`, `plain_lower`; unknown style raises `ValueError`.
4. `unit_hash(palm_id, purpose)`: first 8 bytes of `sha256(f"{purpose}:{palm_id}".encode())`, big-endian int divided by `2**64`.
5. Tests: determinism across two calls and across a subprocess (no reliance on `hash()`); member order irrelevant; any name-part change changes the GUID; 100,000 synthetic palm ids → 100,000 distinct object GUIDs; pin 3 known GUID values and 2 known `unit_hash` values as literals.

## Acceptance criteria

- [ ] Same inputs give the same GUIDs in a fresh interpreter.
- [ ] No collisions in the 100k test.
- [ ] Pinned known values in the test file (changing the scheme fails the test).
- [ ] `unit_hash` is in `[0, 1)` for all tested inputs.
