## Goal

`palmgen/variants.py` picks the closest height variant per palm from the asset manifest, scales it within ±15%, falls back sensibly for unknown species and missing heights, and gives each palm a stable heading. Placeholder mode uses the stand-in model.

## Context

- Rules: plan sections [GEN variant selection](../../plans/detailed/04-fs2024-integration.md#gen-variant-selection) and [Asset manifest fields palmgen reads](../../plans/detailed/04-fs2024-integration.md#asset-manifest-fields-palmgen-reads).
- Load the manifest only through ASSET's loader `palmcore.assets.manifest.load_manifest(path) -> Manifest` (ASSET-005; `palmcore/assets/` is ASSET-owned, not ARCH). `palmgen/variants.py` converts the typed `Manifest` into `Variant`s and adds GEN's checks (duplicate `(species, variant)`, `native_height_m <= 0` → `InputError`); it never parses the JSON itself.
- ASSET-015 (Mexican fan palm in-sim review) depends on this task, so it can review the species at a test site via manifest-driven placement.
- The real `assets/manifest.json` comes from ASSET-100 (Phase 3). This task works on a fixture manifest; GEN-019 checks the real one. Plan 05 lists variant selection under Phase 3; it's done in Phase 2 because the pipeline needs one code path for both modes.

## Steps

1. `Variant`, `Selection` dataclasses; `load_manifest(path)` wrapping `palmcore.assets.manifest.load_manifest` and applying the GEN validation rules from the plan.
2. `select_variant(palm, variants, priors, clamp)` implementing steps 1-4 of the plan.
3. `placeholder_selection(placeholder_model) -> Selection` (scale 1.0).
4. `heading_deg(palm_id)`.
5. Fixture `manifest_small.json` in the ASSET manifest format (`schemas/asset-manifest.schema.json`, validated by the ASSET loader): species in `palms_small.geojson` except the unknown one; one species with two same-height alternates.
6. Tests: closest variant by log ratio; tie → lower; alternates spread by hash; clamp at 0.85/1.15; species fallback by priors; height missing uses the median; heading stable and in `[0, 360)`; manifest validation errors.

## Acceptance criteria

- [ ] All selection rules covered by tests.
- [ ] Same palm always gets the same variant, scale and heading.
- [ ] Invalid manifests raise `InputError` with the offending entry.
