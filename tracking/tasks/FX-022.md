## Goal

STAGE B, coarse. Only after FX-100 = GO; on NO-GO this task is dropped. Find out whether the inpainting model from FX-100's chosen configuration can run on small tiles on the GPU fast enough, via ONNX Runtime with DirectML or via TensorRT.

## Context

- Known blocker: LaMa's Fourier convolutions use FFT ops; export and runtime support for them in ONNX, DirectML and TensorRT is VERIFY. Fallback candidate: an FFT-free inpainting network such as MI-GAN (VERIFY licence and ONNX availability).
- Tile sizes and per-tile CPU/GPU times from Stage A are in `data/fx/*/metrics/inpaint-*-timing.json` and the FX-100 report.
- Network is needed for runtime/toolkit downloads and any alternative model weights.

## Steps

1. Export the chosen model to ONNX in `palmfx/offline/export_onnx.py` at fixed tile sizes 256² and 512²; record opset, any unsupported ops and workarounds.
2. Check numerical match against PyTorch on 20 real tiles (mean absolute difference in 8-bit units).
3. Benchmark in `palmfx/addon/bench/` (small C++ or Python harness): ONNX Runtime + DirectML, and TensorRT if available on the GPU, batch 1 and 4, FP16 and FP32; median and p95 ms per tile after warm-up.
4. If LaMa can't be exported or is too slow, try the FFT-free fallback and repeat steps 1-3.
5. Write `palmfx/docs/inference-benchmark.md`: GPU, driver, runtime versions, table of results, verdict for FX-024's budget.

## Acceptance criteria

- [ ] ONNX export either works (with match numbers) or fails with the exact unsupported ops recorded.
- [ ] Benchmark table for at least one runtime on the user's GPU.
- [ ] Recommendation: which runtime and model to use in the add-on, or "none fits".
