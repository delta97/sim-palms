## Goal

`palmgen/report.py` turns generation and compile results into `build_report.json` and a readable `build_report.md` with exactly the fields in the plan.

## Context

- Field list, order, warning codes and volatile keys: plan section [Build report fields](../../plans/detailed/04-fs2024-integration.md#build-report-fields).
- Inputs are the dataclasses in `palmgen/model.py` (GEN-001). Build them by hand in tests.

## Steps

1. `build_report_dict(gen, comp, checks)`: keys in plan order; `result` = `FAIL` if any check failed or `comp` exit code non-zero; warnings grouped by code with count and first 20 messages; `variants` aggregated from placements.
2. `render_report_md(report)`: `# Build report: <package_name>`, identity bullets, then one Markdown table per section in order; empty sections print `_None._`.
3. `write_reports(project_dir, report)` via `xml_writer.write_if_changed` if available, else plain write.
4. `strip_volatile(report)` helper removing `timings`, `fspackagetool`, `inputs.*.path` (used by goldens).
5. Snapshot test: fixed dict → `tests/fixtures/palmgen/report/expected.md`; key-order test; FAIL logic test.

## Acceptance criteria

- [ ] JSON keys and order match the plan.
- [ ] Markdown snapshot test passes.
- [ ] `strip_volatile` output is stable between two runs with different timings.
