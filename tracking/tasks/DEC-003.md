## Goal

The user picks the language for `palmlive` (region manager and the spawner used in the bake-off), recorded in ADR-0004 before LIVE-001 coding starts.

## Context

- Plans: `plans/01-architecture.md` tech stack (C# / .NET 8, SDK managed SimConnect wrapper); `plans/04-fs2024-integration.md` sections 5 and 6; `plans/07-risks-and-open-questions.md` open question 3.
- Procedure: `plans/detailed/07-risks-and-open-questions.md#how-every-decision-task-runs`.
- Timing: this decision comes **before** DEC-007, not after it. The Phase 5 bake-off (LIVE-009) needs a working spawner (LIVE-008), which needs a language, so DEC-003 cannot wait for ADR-0008. Key input is SPIKE-005. If DEC-007 later picks static, the app needs only folder links and a "sim is running" check, and the user may revisit the split option (Python region manager) in a new DEC task.
- Other evidence: SPIKE-005 notes (C# script worked or not); a check of the main Python SimConnect binding(s): MSFS 2024 support, support for `SimConnect_AICreateSimulatedObject_EX1` and `SimConnect_AIRemoveObject`, last release date, open issues.
- Options: (1) C# .NET 8; (2) Python with a community binding; (3) split: Python region manager using `palmcore`, C# spawner only if live.
- Default if unclear: C# .NET 8 (plan default).
- Repo convention: `palmlive/` is the C# location; a Python outcome changes that layout.

## Steps

1. Read SPIKE-005's log and findings.
2. Check the Python binding(s): record package name, repo URL, latest release date, whether 2024 is mentioned, and whether the two AI object calls are exposed (search the source). Requires a quick web lookup; if unavailable, mark VERIFY.
3. Ask the user which language they would rather maintain.
4. Write `tracking/decisions/ADR-0004-companion-app-language.md` (Status `proposed`) with options, the binding check, and a recommendation; state that it precedes the placement decision (ADR-0008) and what would make it worth revisiting if static wins.
5. User decides. Consequences:
   - C#: `palmlive/` C# solution (PalmLive.App, .Core, .SimConnect, .Tests) and xUnit as planned.
   - Python: `palmlive/` becomes a Python package that imports `palmcore`; tests move to pytest; note to ARCH and LIVE owners to update LIVE-100/101 and the layout.
   - Split: both, with the boundary stated.
6. Add a one-line `Decided (ADR-0004): ...` note to the companion app section of `plans/detailed/04-fs2024-integration.md` (if missing, note in the ADR).
7. Run `python3 scripts/tasks.py validate`.
