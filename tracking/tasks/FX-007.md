## Goal

Two captured sessions (`low` and `obl`, 60 frames each) of colour + packed depth + pose over real blobs at the DEC-004 test block, and a written capture procedure anyone can repeat.

## Context

- Settings, cadence, packing and fallbacks are in the plan_ref (A2). Use FX-001's `depth-access.md` for ReShade flags and network settings, FX-006's `camera-simvars.md` for the view and conventions.
- SCAN-100's `palms.geojson` for the block is used to plan a straight pass that crosses at least 5 palms the sim draws as blobs.
- Frames are large and stay in `data/fx/` (gitignored). Do not commit them. The small committed fixture is built later in FX-013.
- If FX-001's verdict is `DEPTH-UNAVAILABLE`, do not run this task: set it to `blocked` and log why.

## Steps

1. Read `palmfx/docs/depth-access.md` and `palmfx/docs/camera-simvars.md`. Copy the ReShade flags, view choice and `simvar_conventions` into a draft `session.json` template.
2. Install `palmfx/offline/capture/PalmFxDepthPack.fx` in ReShade, enable it as the only effect, turn on "save before and after" screenshots (or note the fallback in use). Point the screenshot folder at `data/fx/<sid>/raw/reshade/` if ReShade allows it, otherwise copy after.
3. Check the shader once: take one screenshot pair, run `python -c "from palmfx.offline.depth import read_depth_png; ..."` to decode it, and view `ln d` as an image; it must match `DisplayDepth.fx` qualitatively (same near/far ordering, sky = 0). If not, fix the flags or the shader source flag (raw vs linearised) and record it.
4. Plan the pass on `palms.geojson` over aerial imagery: a straight line, start point, heading, altitude, and which palm ids should be in view. Save it as `palmfx/docs/capture-procedure.md` section "Pass plan".
5. Set the sim per the plan_ref settings list (resolution, DX12, upscaler TAA or DLAA at 100 %, frame generation off, UI hidden, clear, noon, photogrammetry on, sim rate 0.25×). VERIFY that 0.25× is offered; if not, use the lowest available rate and recompute `--interval-ms` so `sim_step_ms ≤ 33` if possible.
6. Session `low` (30-60 m AGL): `palmfx capture --session data/fx/<YYYYMMDD>-<site>-low-01 --frames 60 --interval-ms 133 --key <key>`. Check the pair count afterwards. If ReShade drops files, raise the interval, retry, and record the real `sim_step_ms`.
7. Session `obl` (about 150 m AGL): same.
8. Paint `calib/static_occluder.png` (0/255) if any aircraft or cockpit pixels are visible; otherwise write an all-zero PNG.
9. Fill in `session.json` for both sessions (all fields in the plan_ref "Session data formats").
10. Write `palmfx/docs/capture-procedure.md`: settings list as actually used, pass plan, commands, problems hit and fixes, and a checklist for repeating the capture.

## Acceptance criteria

- [ ] Two session folders exist under `data/fx/`, each with ≥ 30 (target 60) colour/depth pairs and matching `triggers.csv` rows.
- [ ] `poses.csv` covers the whole capture window.
- [ ] `session.json` complete for both, including `sim_step_ms`, ReShade flags and `simvar_conventions`.
- [ ] At least 5 blobs from the pass plan are visible in each session.
- [ ] `palmfx/docs/capture-procedure.md` is complete enough to repeat the capture without this task file.
