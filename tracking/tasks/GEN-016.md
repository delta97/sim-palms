## Goal

`palmgen build` compiles the Phase 1 test region on the Windows PC with all output checks passing, and the wrapper's constants (BGL naming, log patterns, process names) match reality.

## Context

- Plan section [GEN in-sim validation](../../plans/detailed/04-fs2024-integration.md#gen-in-sim-validation).
- Input: the test region's `palms.geojson` and buildings from SCAN-100 (region chosen by DEC-004). Use `--models placeholder` (no real models until Phase 3).
- Run the airport fetch first if the test region YAML enables the airport mask: `palmgen masks airports --region <name>` (needs network).

## Steps

1. On the Windows PC: `python -m palmgen build --region <test> --models placeholder -v`.
2. If any check fails because a constant is wrong (BGL name, log pattern, process name, output folder), fix it in `palmgen/build.py` with a comment citing this run, and rerun.
3. Save the real success log as `tests/fixtures/palmgen/fspackagetool/real_success.log` and add a unit test case using it.
4. Open the generated project in Dev Mode's Project Editor, build, confirm it loads without errors and polygons appear at the test block.
5. Record in `tracking/logs/GEN-016.md`: sim and SDK versions, command, build time, counts from `build_report.md`, every constant changed and why.

## Acceptance criteria

- [ ] `palmgen build` exits 0 on the Windows PC; `build_report.md` result PASS.
- [ ] Project opens and builds in Dev Mode.
- [ ] Unit tests still pass on Linux with the real log fixture.

## Verification

On the Windows PC:
```powershell
python -m palmgen build --region <test> --models placeholder -v; echo $LASTEXITCODE   # expect 0
Get-Content build\palmfix-<test>\build_report.md | Select-String "PASS"
```
On Linux: `pytest tests/unit/palmgen/test_build.py -q`.
