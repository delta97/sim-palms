## Goal

The user decides where `.blend` sources, large textures and exported glTF/bin files live, and whether visual-test screenshots (`tests/visual/**`, `tests/visual/lineup-*/**`) are committed as JPEG q90 in plain git or through Git LFS, recorded in ADR-0009 before the first asset binary or screenshot set is committed. This keeps the repo usable for agents in worktrees and keeps licensed files out of places their terms forbid.

## Context

- Repo layout: `plans/01-architecture.md` (`assets/blender/`, `assets/PackageSources/`).
- Procedure: `plans/detailed/07-risks-and-open-questions.md#how-every-decision-task-runs`.
- Evidence: `docs/licenses/models-and-tools.md` (RISK-002) for storage clauses of licensed models; ADR-0003 (DEC-002) if already decided.
- Options: (1) Git LFS; (2) external storage (cloud drive or release assets) plus a manifest with SHA-256 hashes and a fetch script; (3) plain git with a size cap check; (4) `.blend` sources outside the repo, only exported files committed.
- Default if unclear: Git LFS for `assets/blender/**` and binary textures (`*.png`, `*.tif`, `*.ktx2`) and exported `*.bin`/`*.glb`; licensed source files never in a public repo.
- VERIFY current GitHub LFS free storage and bandwidth limits at decision time.
- Screenshots: `plans/detailed/06-testing.md` (open question 8) proposes JPEG q90, max 2560 px, committed in plain git, raw PNGs gitignored; `plans/detailed/03-palm-assets.md#large-file-policy` proposes LFS for `*.png` under `tests/visual/`. Decide one rule for both.
- Implementation: ASSET-008 (depends on this task) applies the decision (`.gitattributes`, `assets/README.md`).
- Risk: R-19.

## Steps

1. Ask the user whether the GitHub repo is public, private or undecided.
2. Estimate size (assets and screenshots: about 3 JPEGs × variants × 5 sites per visual run): 5 species × 2-3 variants; `.blend` per variant (assume 20-100 MB), textures at 2K-4K PNG (assume 5-20 MB each). Write the estimate with assumptions.
3. Look up current GitHub LFS quotas (record URL and date).
4. Write `tracking/decisions/ADR-0009-asset-binary-storage.md` (Status `proposed`) with options, the size estimate, quota numbers, license storage constraints, and the default.
5. User decides. In Consequences, name ASSET-008 as the implementation (`.gitattributes` patterns for assets and, if chosen, `tests/visual/`; or the external-store manifest/fetch-script equivalent) and the screenshot rule for TEST-102. Do not implement it in this task.
6. Add a one-line `Decided (ADR-0009): ...` note under the repo layout section of `plans/detailed/01-architecture.md` (if the file is missing, note that in the ADR).
7. Run `python3 scripts/tasks.py validate`.
