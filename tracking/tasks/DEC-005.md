## Goal

The user confirms the reference PC and sim settings and the performance budget, recorded in ADR-0006 before TEST-103 performance runs. The bake-off (DEC-007) and GATE-P5 measure against it.

## Context

- Plans: `plans/06-testing.md` section 5 (metrics, 3 runs per setup, starting budget about 5% average frametime and no added stutter); `plans/07-risks-and-open-questions.md` open question 5.
- Procedure: `plans/detailed/07-risks-and-open-questions.md#how-every-decision-task-runs`.
- Options: (1) relative: at most +5% average frametime, 1% low FPS drop at most 5%, no stutter increase; (2) absolute: at most N ms added per frame at the user's target FPS; (3) tiered: one budget per graphics preset.
- Default if unclear: option 1, measured on the user's own PC at their usual settings; "no stutter increase" means stutter events (frames over 2x median) within the spread of the three no-fix runs.
- Hardware facts can be collected any time earlier; the decision is due before TEST-103 runs.
- Risk: R-10.

## Steps

1. Ask the user for: GPU, CPU, RAM, OS build, display resolution and refresh rate, sim graphics preset, terrain LOD and object LOD sliders, upscaler (DLSS/FSR/TAA) and frame generation on/off, target FPS, whether they fly VR.
2. If TEST-103 already has a no-fix baseline run, copy its average FPS, 1% low and 99th percentile frametime.
3. Write `tracking/decisions/ADR-0006-performance-budget.md` (Status `proposed`): reference hardware table, settings table, the options with numbers, and the default.
4. User decides. Decision states exact thresholds (numbers and units) and the reference settings to keep fixed.
5. Consequences: TEST-103 report script thresholds; GATE-P5 pass criteria; LOD budgets (ASSET) and spawn cap (LIVE) tighten if the budget is tighter than the default.
6. Add a one-line `Decided (ADR-0006): ...` note to the performance section of `plans/detailed/06-testing.md` (if missing, note in the ADR).
7. Run `python3 scripts/tasks.py validate`.

## Acceptance criteria

- [ ] ADR-0006 lists the reference hardware and settings.
- [ ] Decision gives numeric thresholds for average frametime, 1% low and stutter.
- [ ] Status `accepted` (or `proposed` with default applied provisionally).
- [ ] `plans/detailed/06-testing.md` carries the decision note.
