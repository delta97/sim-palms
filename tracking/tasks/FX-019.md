## Goal

Run the whole offline chain on both real sessions with fixed parameters, produce every metric C0, C1 and C3 need, and build the judging packet for FX-020.

## Context

- Runs where `data/fx/` and a GPU are (normally the user's PC). CPU works but LaMa at full resolution is slow; log the device.
- Criteria are in the plan_ref. Thresholds are frozen; parameter tuning is allowed only for the heuristic mask (on the 6 hand-labelled frames) and must be recorded with before/after numbers.
- Configurations to evaluate: masks {`project-depth`, `heuristic`, `hand`} × backend {`lama`, `telea`} × variant {`none`, `reuse`, `blend-a0.5`, `blend-a0.8`}. `hand` masks exist only on 6 frames, so they're used for C1 and as a still-only reference, not for temporal metrics.

## Steps

1. `palmfx/offline/commands/run_stage_a.py`: `palmfx run-stage-a --session DIR --palms GEOJSON [--device cuda]` runs mask-project, mask-heuristic, mask-compare (each automatic vs hand, project-depth vs heuristic), inpaint (lama, telea), stabilise (4 variants), flicker, composite (procedural sprites) for one session; skips steps whose outputs exist unless `--force`; writes `metrics/stage-a-summary.json` with C0, C1, C3 inputs and results per configuration.
2. Run it on both sessions. If heuristic C1 fails, tune `heuristic.yaml` once on the hand frames, record old/new values and metrics in the runlog, re-run.
3. Build the packet: `palmfx judge-pack --session <low>,<obl> --inputs <the top configurations: for each automatic mask method, the variant with the best C3 for lama, plus telea-none as a reference> --stills 30 --seed 1`.
4. `tests/unit/palmfx/test_sample_seq.py`: on `tests/fixtures/palmfx/sample-seq/` (to tmp): ingest gives 5 frames with poses; `project-depth` and `heuristic` run; IoU vs hand ≥ floors recorded now in the test as constants (set to 0.8 × the values measured on the fixture today); Telea inpaint runs.
5. Write `palmfx/docs/stage-a-runlog.md`: commands, device, run times, any tuning, summary tables for C0, C1, C3 per configuration, the packet path and the configurations in it (names only in the runlog, not in the packet).

## Acceptance criteria

- [ ] `metrics/stage-a-summary.json` exists for both sessions.
- [ ] C0, C1, C3 values recorded in the runlog for every configuration.
- [ ] Judging packet built and blinded.
- [ ] `test_sample_seq.py` passes in a Linux container.
