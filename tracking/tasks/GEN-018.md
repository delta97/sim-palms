## Goal

`palmgen index --region X` writes `palmfix-<region>.palms.sqlite` (SQLite + R-tree) with the palms a static build would place, their SimObject titles and headings, for the live spawner. A small committed fixture serves as the cross-language contract for palmlive.

## Context

- Schema and rules: plan sections [Spatial index schema](../../plans/detailed/04-fs2024-integration.md#spatial-index-schema) and [GEN spatial index export](../../plans/detailed/04-fs2024-integration.md#gen-spatial-index-export).
- Python's `sqlite3` must have the R-tree module; check at start (`CREATE VIRTUAL TABLE temp.t USING rtree(id, a, b)`) and raise `ToolUnavailableError` with a clear message if not.
- `simobject_title` values come from the manifest (ASSET-101 fills them for real; the fixture manifest has them).

## Steps

1. Write `palmgen/sql/palm_index_v1.sql` exactly as in the plan.
2. `export_index(rows, out_path, meta)`: write to `<out>.tmp`, execute DDL, insert rows in `palm_id` order with ids 1..N, insert R-tree rows, insert meta, `VACUUM`, rename over the target.
3. `run_index(opts)`: `pipeline.select_placements(opts)` with `models=library`; missing titles → `InputError` unless `--allow-missing-titles` (skip them, warn); write file into the project dir; set `index_file` in `palmfix_build.json` (create the file if absent with the generate-time fields).
4. Generate `tests/fixtures/palmlive/index_small.sqlite` from the small fixtures with `--data-version 2026-11`; make the export deterministic (no timestamps in meta) so regenerating gives identical bytes, and test that.
5. Tests: row count equals `select_placements`; R-tree bbox query returns the expected palms; meta keys present; missing-title paths.

## Acceptance criteria

- [ ] Index contains exactly the palms a static build places.
- [ ] Regenerating the fixture yields byte-identical output.
- [ ] `palmfix_build.json` gets `index_file`.
