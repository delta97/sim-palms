## Goal

The "draw" step: put a palm sprite at each erased blob, scaled from depth and depth-tested so nearer objects stay in front. Judged as information only in Stage A.

## Context

- Sprite format, depth fill, placement, depth test and blend rules are in the plan_ref (A13).
- Placements come from the `project-depth` instance JSON (FX-010): `palm_id`, `base_uv`, `z_m`, plus `height_m` from palms.geojson.
- Procedural sprites are enough for Stage A. ASSET-100 renders can replace them later via the same `sprites.json` format; no dependency on ASSET-100.

## Steps

1. `palmfx/offline/sprites.py`: `make_procedural_sprites(out_dir, n=3, seed=0)` draws RGBA palms (tapered trunk, 10-14 arched fronds, slight colour variation) at 512 px tall and writes `sprites.json` with `height_m`, `base_px`, `top_px`, `species: "generic"`, `licence: "generated"`. `load_sprites(dir) -> SpriteSet`.
2. `palmfx/offline/composite.py`: `Placement` dataclass; `placements_from_instances(mask_json, palms) -> list[Placement]`; `fill_depth(depth_m, mask)`; `composite_palms(rgb, depth_filled, placements, sprites, K)` with premultiplied alpha, depth test `depth_filled ≥ z_b − max(1.0, 0.02·z_b)`, brightness gain clamp [0.8, 1.2]; far-to-near drawing order.
3. `palmfx/offline/commands/composite.py`: `palmfx composite --session DIR --input <stab dir name> --sprites DIR --palms GEOJSON [--make-sprites]` writes `composite/<name>/NNNNNN.png`.
4. `tests/unit/palmfx/test_composite.py`: sprite height in pixels equals `fy·height_m/z` within 2 px; base pixel lands at `base_uv` within 1 px; a nearer occluder (synthetic building) hides the sprite's covered part; pixels with no sprite are unchanged; `fill_depth` inside a blob on flat ground returns ground depth within 5 %.
