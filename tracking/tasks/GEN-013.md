## Goal

`palmgen/build.py` finds and runs `fspackagetool`, refuses or warns when the sim is running (per SPIKE-004), logs output, and checks the compiled result (exit code, one BGL per tile, element counts, log errors). Fully unit-tested with a fake runner on Linux.

## Context

- Spec: plan section [GEN fspackagetool wrapper](../../plans/detailed/04-fs2024-integration.md#gen-fspackagetool-wrapper).
- Facts come from SPIKE-004's findings note ([SPIKE-004 fspackagetool measurements](../../plans/detailed/04-fs2024-integration.md#spike-004-fspackagetool-measurements)): install path, output layout, BGL naming, exit codes, log error/warning line patterns, sim process names, and whether builds can run with the sim open. Only the flags `-outputdir` and `-nopause` are known; don't add others.
- If SPIKE-004 left something unrecorded, implement the function with a clear `# VERIFY:` comment and a conservative default, and list it in the Log for GEN-016 to calibrate.

## Steps

1. Copy SPIKE-004's sample success and failure logs into `tests/fixtures/palmgen/fspackagetool/success.log` and `failure.log`; add a `README.txt` line naming their source (SDK version, date).
2. `find_fspackagetool(explicit)`, `SIM_PROCESS_NAMES`, `BUILD_WITH_SIM_OPEN: bool` (from SPIKE-004), `sim_is_running(names, runner)`.
3. `compile_package(project_xml, out_dir, tool, timeout_s, log_path, runner)`: command list from the plan; on `subprocess.TimeoutExpired` kill and raise `CompileError`.
4. `expected_bgl_name(tile_file) -> str` and `find_bgls(out_dir) -> dict[str, Path]` from the SPIKE-004 output listing.
5. `ERROR_PATTERNS`, `WARNING_PATTERNS` (compiled regexes) and `scan_log(path) -> (warnings, errors)`.
6. `check_outputs(gen, comp, out_dir, ts, scene_dir) -> list[Check]` with the five checks named in the plan.
7. Tests with a fake runner: success writes fake BGLs → all checks pass; missing one BGL → `bgl_per_tile` fails; non-zero exit → `CompileError`; timeout; tool not found → `ToolUnavailableError`; non-Windows detection (monkeypatch `sys.platform`); sim running with and without `BUILD_WITH_SIM_OPEN`.

## Acceptance criteria

- [ ] All wrapper behaviour covered by fake-runner tests; no test needs Windows.
- [ ] Every SPIKE-004-derived constant cites the findings note in a comment.
- [ ] Unknown facts are `# VERIFY:` comments and listed in the Log.
