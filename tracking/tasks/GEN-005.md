## Goal

`palmgen/geometry.py` turns palms into circumscribed 12-sided exclusion polygons, merges circles within `merge_gap_m` into connected clusters (split when longer than 150 m), simplifies them, and normalises rings for XML output.

## Context

- Algorithms and defaults: plan section [GEN geometry](../../plans/detailed/04-fs2024-integration.md#gen-geometry).
- Use shapely 2.x and pyproj. Use `palmcore` geo helpers for the projection if they offer a local metric projection; otherwise `LocalProjection` here.
- `palm_radius` takes a `GenConfig`-like object; GEN-004 may not be merged yet, so type it with a small `Protocol` holding the attributes you need.

## Steps

1. `LocalProjection(lon0, lat0)` (pyproj `+proj=tmerc +lat_0 +lon_0 +k=1 +ellps=WGS84 +units=m`), `forward`, `inverse`, `geom_to_local`, `geom_to_lonlat` (via `shapely.ops.transform`).
2. `palm_radius(p, cfg, margin_override)` returning `(radius, warning_code | None)` with the precedence and clamping from the plan.
3. `circle_polygon(x, y, r, sides=12, circumscribe=True)`.
4. `merge_clusters(items, gap_m, max_extent_m)`: STRtree, union-find, MST (Kruskal on centre distances, ties by palm_id pair), union of circles and MST-edge hulls; split by removing longest MST edges until each part's bbox diagonal ≤ `max_extent_m`. Return clusters sorted by first member id; report which clusters were split.
5. `simplify_cluster(poly, tol_m, max_vertices)` returning `(poly, simplified_flag)`; raise `GenerationError` if still over the limit after 5 doublings.
6. `normalize_ring(poly_lonlat, orientation, decimals, closed)` per the plan.
7. Tests from the plan list, plus: shuffled input order gives identical output; a single palm gives exactly `sides` vertices.

## Acceptance criteria

- [ ] Circle contains a true circle of radius r and is valid.
- [ ] Merge results: 3 m spacing stays separate, 1.5 m spacing merges (radius 1 m, gap 2 m); every member circle covered.
- [ ] 400 m row splits into clusters each ≤ 150 m diagonal.
- [ ] Output identical for shuffled input.
