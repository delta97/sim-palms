## Goal

`palmfx capture` logs aircraft (and if possible camera) pose every frame and presses the ReShade screenshot key on a fixed interval, with both on one host clock. Also settle which camera variables MSFS 2024 exposes and which view gives a reconstructable camera pose.

## Context

- File formats: `raw/poses.csv` and `raw/triggers.csv` in the plan_ref "Session data formats". Log raw SimVar values; conventions get applied later in `camera.pose_from_simvars`.
- VERIFY items owned here: camera SimVars in 2024 (candidates from the 2020 SDK: `CAMERA STATE`, `CAMERA SUBSTATE`, `CAMERA VIEW TYPE AND INDEX`, `CAMERA GAMEPLAY PITCH YAW`); sign conventions of `PLANE PITCH DEGREES` and `PLANE BANK DEGREES`; which sim-time variable exists; whether the Python binding works with 2024 and offers a per-visual-frame period.
- Binding: try the `SimConnect` package on PyPI first. If it doesn't connect to 2024 or can't request per-frame data, use `ctypes` against `SimConnect.dll` from the 2024 SDK. Record which one in the doc.
- Only one clock: `time.perf_counter_ns()` in the same process for pose rows and triggers.

## Steps

1. `palmfx/offline/capture/pose_logger.py`: `PoseSource` protocol (`read() -> dict | None`); `SimConnectPoseSource` (Windows only; imports guarded); `PoseLogger(source, csv_path)` thread that polls or receives data, stamps `t_host_ns`, writes rows. Request the aircraft variables listed in the plan_ref A3 plus any camera variables given by `--cam-vars`.
2. `palmfx/offline/capture/trigger.py`: `Trigger(key, interval_ms, n_frames, csv_path)` sends the key via Win32 `SendInput` (ctypes) and writes `frame_idx,t_trigger_ns`. Uses a monotonic schedule (`next += interval`) so it does not drift.
3. `palmfx/offline/commands/capture.py`: `palmfx capture --session DIR --frames N --interval-ms MS --key KEY [--cam-vars "CAMERA STATE,..."] [--probe]`. Creates the session with `new_session` if missing. `--probe` prints all requested variables at 5 Hz until Ctrl+C and writes nothing.
4. Probe in the sim: switch through cockpit, external, drone and any locked or fixed views; record which candidate variables change and whether any gives world position, orientation or FOV/zoom. Check pitch/bank signs: nose up on the ground or in a climb, right bank in a turn.
5. Choose the capture view (preference order in the plan_ref A3) and record the initial `cam_offset_body_m` guess and how zoom is fixed.
6. Write `palmfx/docs/camera-simvars.md`: binding used, confirmed variables with units, `simvar_conventions` JSON to paste into `session.json`, chosen view, and remaining VERIFY items.
7. `tests/unit/palmfx/test_pose_logger.py` (runs on Linux): `PoseLogger` with a fake source writes the right CSV header and monotonic `t_host_ns`; `Trigger` with a fake key sender writes N rows with intervals within 5 ms of the target (use a fake clock).
8. Dry run in the sim: 20 frames, check `raw/triggers.csv` has 20 rows, `raw/poses.csv` has at least one row per 20 ms, and the screenshot folder has 20 pairs.

## Acceptance criteria

- [ ] `palmfx capture --probe` connects to MSFS 2024 and prints live values.
- [ ] Dry run produces matching trigger count and screenshot pairs.
- [ ] `palmfx/docs/camera-simvars.md` names the confirmed variables, sign conventions and chosen view.
- [ ] Unit tests pass on Linux without SimConnect installed.
