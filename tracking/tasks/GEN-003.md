## Goal

`palmgen/tiling.py` maps lon/lat to 0.01° tiles named by their south-west corner (`n32p78_w117p26`), with exact integer maths and a round-trip parser.

## Context

- Rules and examples: plan section [GEN tiling](../../plans/detailed/04-fs2024-integration.md#gen-tiling).
- The file name format `tile_<id>.xml` comes from the source plan's package layout.

## Steps

1. `TILE_DEG = 0.01`; `tile_index(lon, lat)` using `ix = math.floor(round(lon * 1e8) / 1e6)` (integer floor division on the rounded int) and the same for lat.
2. `tile_id(ix, iy)`, `parse_tile_id(tid)` (regex `^([ns])(\d+)p(\d{2})_([ew])(\d+)p(\d{2})$`, `ValueError` otherwise), `tile_filename(tid)`, `tile_bounds(tid)`.
3. `assign_polygon_tile(member_points: dict[str, tuple[float,float]]) -> str` using the smallest palm_id's point.
4. `check_bbox(bbox)`: raise `InputError` if `lon_min > lon_max` (antimeridian crossing) or lat out of range.
5. Tests: the plan's example point; points exactly on tile edges (e.g. lon -117.26, lat 32.79) land in the tile whose SW corner they are; negative lat (`s0p01`), positive lon (`e`), lon 0 and ±179.995; `parse_tile_id(tile_id(ix, iy)) == (ix, iy)` for a grid of 1,000 random indices; bounds contain the point.

## Acceptance criteria

- [ ] Example from the plan yields `n32p78_w117p26`.
- [ ] Edge and hemisphere cases pass.
- [ ] Round-trip property holds.
