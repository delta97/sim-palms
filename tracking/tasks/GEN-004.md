## Goal

`palmgen/inputs.py` loads and validates `palms.geojson`, building footprints and the region YAML into `Palm` objects, shapely polygons and a frozen `GenConfig`. It also creates the shared `*_small` fixtures that later GEN tests reuse.

## Context

- Spec: plan sections [GEN inputs](../../plans/detailed/04-fs2024-integration.md#gen-inputs) and [Region config keys palmgen reads](../../plans/detailed/04-fs2024-integration.md#region-config-keys-palmgen-reads).
- Use `palmcore.palms.read_palms` (ARCH-007, which validates with ARCH-002), `palmcore.contract.validate_buildings` (ARCH-002 secondary contract for `buildings.geojson`) and `palmcore.config.load_region` (ARCH-003); don't reimplement schemas.
- `GenConfig` is a mapping of `RegionConfig`: every default in the plan table (exclusion `margin_m` 1.5, `radius_min_m` 1.0, `radius_max_m` 8.0, the other `exclusion.*`, `placement.scale_clamp`, `masks.airports.*` including `path`) is defined once in ARCH-003. Do not repeat defaults here; read them from `RegionConfig`.
- Paths in `RegionConfig` are already absolute (ARCH-003 resolves every relative path against the repo root, not the region file's folder).
- Default inputs are the canonical palmscan outputs `build/scan/<region>/palms.geojson` and `build/scan/<region>/buildings.geojson`.
- The data-version key in collection metadata is ARCH-002's; just return the collection-level members as a dict.

## Steps

1. `GenConfig` frozen dataclass built from `RegionConfig` (no duplicated defaults); `load_gen_config(region_name, config_path)`. Unknown keys under `exclusion` → `logging.warning`. `region` in the YAML must equal `region_name` else `InputError`.
2. `load_palms(path, region)`: validate; map properties to `Palm`; `InputError` on schema failure (first 20 errors), duplicate `palm_id`, or a feature whose `region` differs. Return palms sorted by `palm_id` and the collection-level members (everything except `type` and `features`).
3. `load_buildings(path)`: validate with `palmcore.contract.validate_buildings` (`InputError` on errors); Polygon and MultiPolygon features → list of Polygons (exploded), `make_valid`, drop empties. Missing file → `InputError` with the hint from the plan.
4. Create fixtures per the plan: `palms_small.geojson` (12 palms across 2 tiles with the listed cases; all must pass the ARCH-002 schema), `buildings_small.geojson` (one building touching a palm's circle, one containing a palm; valid against the ARCH-002 buildings schema: `schema_version`, `region`, `building_id`, `source`), `region_small.yaml` (region `fixture-small`, bbox covering both tiles, one inline `mask_out` of kind `mod` around one palm, `masks.airports.enabled: true`). Put a comment block at the top of the YAML describing each case.
5. Tests for each error path and for defaults.

## Acceptance criteria

- [ ] Fixtures validate against the ARCH-002 schema and the ARCH-003 loader.
- [ ] Every `InputError` path has a test.
- [ ] `GenConfig` defaults equal the plan table.
