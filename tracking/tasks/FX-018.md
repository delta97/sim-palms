## Goal

A written, blinded judging protocol and a `palmfx judge-pack` command that builds the packet (shuffled stills, side-by-side videos, score sheets, sealed key). Criteria C2 and C4 come from these scores.

## Context

- Packet layout, scales, controls and viewing rules are in the plan_ref (A14).
- `ffmpeg` must be on PATH for videos; if missing, the command writes stills and sheets and warns. Tests don't need ffmpeg.
- The score sheets must be machine-readable so FX-100 can compute C2/C4 without retyping.

## Steps

1. `palmfx/docs/judging-protocol.md`: setup (monitor, distance, no zoom, lighting), the two passes, still scale 1-5 and shimmer scale 0-2 with the exact wording from the plan_ref, controls, rules (score before opening `key.json`; no re-scoring after the key is opened), how to fill the CSVs.
2. `palmfx/offline/judge.py`:
   - `build_packet(sessions, inputs, n_stills=30, n_controls=3, seed=1, out=None) -> Path`: pick stills evenly across sessions and inputs; number the blobs per still from the instance JSON and write `stills_index.csv` (`still_id, blob_no, bbox`); write controls by inpainting a same-size patch of non-blob, non-sky area with the same backend; random letter labels; `key.json`; empty `scores_stills.csv`, `scores_temporal.csv`.
   - `make_videos(...)`: side-by-side raw | output, `ffmpeg -framerate {60,30} -i %06d.png -c:v libx264 -crf 12 -pix_fmt yuv420p`.
   - `score(packet_dir) -> dict`: reads filled sheets and the key; per configuration: n instances, median, share ≤ 2, control scores; per video: shimmer score; returns C2 and C4 pass/fail per configuration using the plan's thresholds.
3. `palmfx/offline/commands/judge_pack.py`: `palmfx judge-pack --session DIR[,DIR] --inputs <dir>,<dir> --stills 30 --seed 1` and `palmfx judge-score --packet DIR`.
4. `tests/unit/palmfx/test_judge.py`: same seed gives the same packet; no configuration name appears in still or video filenames; `score()` on hand-filled sheets gives the expected C2/C4 results, including the edge cases median exactly 4 and exactly 10 % ≤ 2 (both pass).

## Acceptance criteria

- [ ] Protocol doc complete and matches the plan's scales and thresholds.
- [ ] Packet is blinded (no configuration names visible outside `key.json`).
- [ ] `judge-score` reports C2 and C4 per configuration.
