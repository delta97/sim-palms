## Goal

STAGE B, coarse. Only after FX-100 = GO (via FX-021); on NO-GO this task is dropped. Find out what the add-on sees and where its edits end up under DLSS upscaling, DLSS frame generation and DLSS 5, so we know which modes the real-time fix can support.

## Context

- Nothing here is assumed. The source plan only says DLSS 5 treats engine geometry as a fixed foundation and that generated frames may not pass through the add-on the same way. All behaviour is VERIFY.
- Needs an NVIDIA GPU that supports the modes tested; record which modes the user's hardware can't test.
- Uses FX-021's debug overlay: draw a visible test pattern (e.g. a magenta square at a fixed screen position) and look for it.

## Steps

1. For each mode (TAA/DLAA native; DLSS upscaling; frame generation on; DLSS 5 if available): record colour and depth resolution seen by the add-on and whether depth lines up with colour.
2. Draw the test pattern; capture output with an external recorder (not ReShade) and check whether the pattern appears on every displayed frame or only on rendered ones, and whether DLSS 5 alters it.
3. Note visual artefacts (ghosting of the pattern, smearing) per mode.
4. Write `palmfx/docs/dlss-interaction.md`: table per mode with findings, and a supported / unsupported / unknown verdict per mode.

## Acceptance criteria

- [ ] Every mode the hardware supports has observations; untested modes are listed with the reason.
- [ ] Verdict per mode.

## Verification

Manual: reviewer checks `palmfx/docs/dlss-interaction.md` covers each mode with resolution, alignment and pattern-visibility observations, plus driver and sim build.
