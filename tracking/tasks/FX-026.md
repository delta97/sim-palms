## Goal

The LaMa backend of `palmfx inpaint` (FX-014) runs end to end on a real machine, with the
model weights pinned by checksum in `palmfx/offline/models.lock.json`. This closes FX-014's two
open acceptance criteria and unblocks FX-015, FX-017 and FX-018.

## Context

- Split out of FX-014 on 2026-11-22. FX-014's code is merged to `main` (Telea baseline and
  tiling tested; LaMa backend implemented but never run). FX-014 is `blocked` until this task
  is done; it now depends on FX-026.
- `models.lock.json` already holds the source URL, version, licence and input convention read
  on 2026-11-22. `sha256` is `null` (marked VERIFY): no checksum is published upstream, so it
  must be recorded from the downloaded file. The weights licence on the Hugging Face big-lama
  page was not read yet (VERIFY).
- `LamaInpainter` refuses to load weights whose checksum is not in the lock unless
  `--trust-weights` is passed; with that flag it logs the file's sha256 for you to record.
- `requires: human`: downloading and loading third-party model weights (a pickled PyTorch file
  runs code when loaded) needs the user's explicit OK, and the user chooses the machine. CPU is
  enough for a one-frame smoke run; a GPU only matters for FX-019 timing.
- Weights go in `data/fx/models/` (gitignored). Never commit them.

## Steps

1. With the user's OK, on the chosen machine: `pip install -e ".[dev,fx,fx-lama]"` (adds torch).
2. Read the weights licence on the model page the lock file points at; record it in the lock
   (URL and date read). If the licence forbids the intended use, stop and tell the user.
3. Download `big-lama.pt` into `data/fx/models/`.
4. Run once with `--trust-weights` to get the logged sha256 (or compute it with
   `python -c "import hashlib,sys;print(hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest())" data/fx/models/big-lama.pt`),
   and write it into `models.lock.json`; clear its VERIFY markers.
5. Run `palmfx inpaint --backend lama --device cpu --frames 0-0` on a session with masks (a
   synthetic session from FX-004 is fine), then the same with `--backend telea`.
6. Run the torch-gated LaMa unit test (it is skipped when torch is absent).
7. Tick FX-014's two open acceptance boxes with evidence in its Log and move FX-014 to `review`.

## Acceptance criteria

- [ ] `models.lock.json` has the real sha256 and the weights licence, with source URL and date read.
- [ ] `palmfx inpaint --backend lama` and `--backend telea` both run on the same session; output paths recorded in the Log.
- [ ] The torch-gated LaMa test passes on that machine; `python scripts/ci.py` still passes without torch.
- [ ] FX-014 moved from `blocked` to `review` with its boxes ticked.
