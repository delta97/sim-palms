## Goal

`palmgen` writes the package project file and `PackageDefinitions/<pkg>.xml` from captured templates, and implements the `1.3.0+data2026-11` version scheme.

## Context

- Spec: plan sections [GEN package project and versioning](../../plans/detailed/04-fs2024-integration.md#gen-package-project-and-versioning), [Build output layout](../../plans/detailed/04-fs2024-integration.md#build-output-layout), [Build metadata file](../../plans/detailed/04-fs2024-integration.md#build-metadata-file) (versioning paragraph).
- Inputs: `palmgen/templates/captured/project.xml`, `captured/package_definition.xml`, notes from SPIKE-003. VERIFY items: whether scene files are listed one by one or by folder; whether the version field accepts build metadata (default: write `package_version` only).
- Don't add a `palmfix-assets` dependency declaration; GEN-019 does if needed.

## Steps

1. `version.py`: `PackageVersion(generator, data)` with `.full`, `.package_field`; `parse_version` (regex in plan, `ValueError` otherwise); `resolve_data_version(collection_meta, override)` (override must match `^\d{4}-\d{2}$`; else read the ARCH-002 key; else `InputError`).
2. Convert the two captures into `project.xml.j2` and `package_definition.xml.j2` (same round-trip rule as GEN-009); register both in `templates.yaml`.
3. `project.write_project(ts, project_dir, package_name, version, tile_files)` writes `<pkg>.xml` and `PackageDefinitions/<pkg>.xml` with `write_if_changed`; title `PalmFix <Region Title Case>`, creator `palmfix`.
4. Round-trip tests for both templates; `write_project` output for a fixed input; version parsing tests (valid, invalid, override precedence).

## Acceptance criteria

- [ ] Round-trip tests pass for project and package definition templates.
- [ ] `PackageVersion("1.3.0", "2026-11").full == "1.3.0+data2026-11"`.
- [ ] Missing data version without override raises `InputError`.
