## Goal

A short report that says GO or NO-GO for Stage B, from criteria fixed before judging, with the evidence behind each criterion. GATE-P7 and every Stage B task (FX-021 to FX-025) wait on it.

## Context

- Criteria C0-C4 and the decision rule are in the plan_ref, "Stage A go or no-go criteria". Copy that table into the report unchanged (pre-registration). Don't change thresholds after seeing results; a changed threshold is a separate, labelled re-run, and the original verdict stays in the report.
- Inputs: `palmfx/docs/depth-access.md` (FX-001), `palmfx/docs/stage-a-runlog.md` and `data/fx/*/metrics/stage-a-summary.json` (FX-019), `palmfx/docs/judging/<packet_id>/score-summary.json` and notes (FX-020).
- Early exit: if FX-001 logged `DEPTH-UNAVAILABLE`, write this report straight away as `NO-GO-C0`. Set every not-yet-done task among FX-002..FX-020 to `dropped`. `tasks.py ready` won't list FX-100 then (a dropped dependency doesn't count as done), so claim it directly with `python3 scripts/tasks.py claim FX-100 --owner <you>`.
- Summary of the rule: GO only if C0-C4 all pass for one (automatic mask, backend, variant) configuration. Passing only with hand masks is `NO-GO-C1`.

## Steps

1. Create `palmfx/docs/stage-a-report.md` with sections: Verdict (one line: `GO` or `NO-GO-Cn (<reason>)`), Criteria (copied table), Results per criterion, Chosen configuration, Draw step (information only), What we learned, Effort (actual hours vs the source plan's 10-20 h estimate), Stage B implications, Open VERIFY items.
2. C0: verdict from `depth-access.md`; session and aligned-frame counts from the runlog.
3. C1: per automatic method, instance recall at IoU ≥ 0.3 and median pixel IoU vs hand.
4. C3: per configuration, `median(ratio)`, `p95(ratio)`, baselines, pass/fail, for each session.
5. C2 and C4: from `score-summary.json`; include control-still scores and any "judge over-critical" note.
6. Apply the rule: find a configuration passing all of C1-C4; if several, pick the best C3 median. Write the verdict.
7. Stage B implications: on GO, list which known blockers in the plan's Stage B section are now most urgent, with any evidence from Stage A (e.g. tile sizes and LaMa seconds per tile from `metrics/inpaint-*-timing.json`). On NO-GO, state that the scenery fix stays the answer, and set Stage B tasks to dropped: `python3 scripts/tasks.py set FX-021 dropped --by <you> --note "FX-100 NO-GO"` (repeat for FX-022..FX-025).
8. Human sign-off: the user reads the report and confirms the verdict; log it on this task.
