## Goal

Region packages built with `--models library` show ASSET-100's palms at the right place, height and heading, sitting on the ground, with the model library in its own `palmfix-assets` package.

## Context

- Plan section [GEN in-sim validation](../../plans/detailed/04-fs2024-integration.md#gen-in-sim-validation); asset acceptance checks in `plans/03-palm-assets.md` section 6.
- VERIFY: whether a region package must declare a dependency on `palmfix-assets` for model GUIDs to resolve. Find out here; if needed, add it to `package_definition.xml.j2` using the format the SDK docs or a Dev Mode capture show (don't guess element names; capture from Dev Mode if necessary).
- Manifest format is ASSET-100's; adjust `load_manifest` if it differs from the fixture form.

## Steps

1. Validate `assets/manifest.json` with `load_manifest`; fix the loader if the real format differs (update `manifest_small.json` to match and rerun unit tests).
2. Install `palmfix-assets` in Community; `python -m palmgen build --region <test> --models library`.
3. In the sim at T1: palms visible at every former blob; species match; heights plausible (compare 5 palms against `height_m`); bases not floating or sunken; headings vary.
4. If models don't appear, test the dependency declaration hypothesis and fix the template; record what worked.
5. Screenshots per TEST-102 into `tests/visual/T1/<date>/library/`; write `tracking/logs/GEN-019.md`.

## Acceptance criteria

- [ ] Real palms appear at T1 from the region package with the separate assets package.
- [ ] No floating or sunken bases on flat ground.
- [ ] Dependency question answered and recorded.
- [ ] Unit tests pass after any loader change.

## Verification

Manual on the Windows PC: screenshots in `tests/visual/T1/<date>/library/` reviewed against the checklist. On Linux: `pytest tests/unit/palmgen -q`.
